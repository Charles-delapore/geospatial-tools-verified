## 二、各域亮点 Top 5

### 领域一：复杂网络及其优化
1. **NetworkX 3.7**——通用图分析事实标准，17,392 stars，实测通过（Karate 图 Louvain 划分等）。
2. **igraph 1.0.0 + leidenalg 0.12.0**——C 核心高性能 + Leiden 社区发现的黄金组合，实测通过。
3. **Infomap 2.16.0**——信息流社区发现，实测通过。
4. **OSMnx 2.1.1**——空间网络事实标准，离线 XML 实测通过（小图 `basic_stats` 有边界异常，未在真实路网复现）。
5. **NetworkX-Temporal 1.4.5**——时序网络新兴标准件（20 stars 但 2026-11-13 仍活跃），实测通过。

### 领域二：景观生态
1. **landschaft**——2026 年新项目，合成 40×40 栅格实测通过（212 patches、约 60 个指标，SHDI 1.059），卖点是复现 FRAGSTATS 结果。
2. **PyLandStats**——114 stars，GPL-3.0，2026-11-09 仍活跃，import 与核心函数实测通过。
3. **Circuitscape.jl**——150 stars，MIT，2026-10-28 活跃，连通性分析标杆（Julia，本机未实测）。
4. **Graphab**——顶刊点名组合之一，仓库在 GitLab 上容易漏掉；连通性图论主力。
5. **InVEST + Linkage Mapper**——生境建模与廊道应用组合；格局指数的定义基准仍是闭源 FRAGSTATS。

### 领域三：地理人文福祉
1. **OpenTripPlanner（OTP）**——2,776 stars，公交可达性事实标准底座（Java，本机未实测）。
2. **R5 生态（r5 + r5r + r5py）**——研究级出行时间矩阵的快车道（Java/R，本机未实测）。
3. **PySAL access**——可达性测度方法箱（2SFCA、E2SFCA、RAAM），实测通过。
4. **r2sfca**——把 2SFCA 与 i2SFCA 统一成一个参数（CRAN 包；GitHub 仓库 404）。
5. **GOAT**——15 分钟城市的 WebGIS 工作台（后端 Java，本机未实测）。

### 领域四：复杂空间分析与相关性建模
1. **mgwr**——GWR 经典，438 stars，复跑验证通过（合成数据 R²=0.974）。
2. **GSTools + PyKrige**——地统计双旗舰，GSTools 复跑验证通过（变差函数拟合与普通克里金）。
3. **esda**——PySAL 空间自相关，263 stars，复跑验证通过。
4. **City2Graph**——1,985 stars，2026 年增长最快的空间图新工具（CEUS 2026 论文配套），仅静态核查。
5. **spml**——PySAL 2025 年空间机器学习新旗舰（原 gwlearn），**部分通过**：`fit()` 可跑但不生成局部系数，`predict()` 报 `AttributeError`（开发版 0.1.dev1 缺陷）。

### 领域五：地理信息可视化
1. **GeoLibre**——半年 8.6k stars（创建于 2026-05-27），Web/桌面/移动/Jupyter 一体，打印布局直接回应期刊版式要求；未本地构建。
2. **lonboard**——发版密度最高（0.13→0.17 一年五版），deck.gl GPU 渲染质感与性能最佳，但默认无图例。
3. **MapLibre GL JS**——开源矢量底图首选，12,084 stars；矢量瓦片注记与道路网使地图“像地图”。
4. **PyGMT**——补验后实测出图（GMT 6.5.0 + pygmt 0.19.0），GMT 血统使出版级海岸线/比例尺/指北针原生，理论上最接近期刊规范。
5. **Bertin.js**——原生标题/脚注/比例尺/图例，出图项目中最接近期刊四件套；但已停更（2023-10 后无推送），仓库已由 neocarto/bertin 迁移至 riatelab/bertin。

### 领域六：跨领域 skills 与 MCP
1. **qgis-mcp（nkarasiak 版）**——125 个工具，GPL-2.0，436 stars，工具列表实测通过（两次日志一致）；但未连接 QGIS，仅验证“服务器能启动、工具已注册”。
2. **gis-mcp（mahdin75）**——91 个工具，全域最多，但带病：5 个可选模块缺失，stdout 打印曾污染 JSON-RPC 流。
3. **gis-mcp-server（LocuSync）**——46 个工具，地理编码/路径/空间分析，走 Nominatim、OSRM 公共服务。
4. **OSM MCP 三选一**：jagan 版（12 个工具）与 ni-c 版（11 个工具）均实测通过；另有一同名项目未验证。

## 四、期刊标杆线结论（单独说明）

六域共抽样 **54 篇** 2024–2026 年顶刊文章（另有 1 篇旁证）：复杂网络 11 篇（Nat. Commun. 4、Network Science 3、Applied Network Science 4）、景观生态 8 篇、福祉 12 篇、空间分析 11 篇（IJGIS 3、Geogr. Anal. 2、CEUS 3、Nat. Commun. 3）、可视化 11 篇（三刊：CaGIS、IEEE TVCG、Journal of Maps）+ 1 篇《The Cartographic Journal》旁证、skills-mcp 轻量核查 1 篇。

**四条跨域共识：**
1. **顶刊点名率最高者仍是经典旗舰**：igraph、NetworkX、Circuitscape/Graphab、FRAGSTATS、INLA、OTP/R5——新工具要证明“与标杆一致”才能进顶刊，复现标杆结果是正确的进场策略。
2. **方法自述 + 通用工具是主流**：多数顶刊实证用 R/Python 通用统计与 GIS 自述方法，而非清单专用引擎；清单工具被明确点名的比例很低（如复杂网络 11 篇中仅 igraph 与 NetworkX 被点名；福祉 12 篇中仅 OTP、R5、r5r、RAAM 被点名）。
3. **代码公开率参差**：空间分析抽样 11 篇中 8 篇公开代码；福祉 12 篇中无一篇给出公开代码仓库链接；景观生态 8 篇中仅方法论文真正公开代码。投稿趋势是收紧“on request”，优先选 CC BY 开放获取 + 公开仓。
4. **MCP/Skills 尚未进入顶刊方法**：2024–2026 年顶刊中明确以 Skills+MCP 为方法的地理论文仅检索到 1 篇（Agentic SWMM，2026，MDPI《AI for Engineering》创刊号）；期刊层面采用证据不足。

## 五、期刊级制图标准小结（8 条可执行规范）

综合六域期刊抽样提炼（来源：可视化域 8 条、空间分析域 5 条、景观生态域 5 条、福祉域 5 条、复杂网络域 5 条，取交集与并集；福祉域配色/字体细节因 PDF 文本层提取无法判断，已写“未查到”）。用这 8 条反向评判实测工具：

1. **分面先行，一图一结论**：多变量/多时相用 a/b/c 分面或小多图，不用单图硬塞；每个分面共用同一图例与比例尺；多面板按“对照逻辑”（方案 A vs 方案 B、全貌 vs 局部、证据链递进）组织，不按变量堆叠；面板用字母编号 + 每面板小标题，正文按编号引用。
2. **配色讲语义**：顺序数据用顺序色、双向数据用发散色、类别用定性色；分级不超过 5–7 级；禁彩虹色；同一类别在全文所有图中保持同一颜色；成图后做一次色盲模拟检查（至少 protanopia/deuteranopia），并在图注中说明。
3. **底图退后**：底图用浅色/单色（CartoDB Positron 类），注记与道路只作参照；数据层颜色饱和度须高于底图；交互图须提供底图开关；避免彩色卫星底图抢夺主题信息。
4. **四件套齐全**：每幅投稿图必须有图例、比例尺（或比例说明）、指北针（非正北投影时尤甚）、数据来源与投影说明；比例变形要如实标注；研究区图须标出行政/生态边界与关键地名。
5. **字体三级**：标题 ≥12 pt、图例/轴注 9–10 pt、脚注（来源）8 pt；同一图内不超过两种字体；中文图须显式指定中文字体（如 Noto Sans CJK SC），不得依赖 matplotlib 默认 DejaVu（中文会成方框，本次实测已验证）。
6. **统计图与地图分工**：数值比较进表格（均值 ± 标准差），地图只表达空间分布；不在地图上堆数值标注；分布/不平等类结论用 Lorenz/Gini 图，空间格局用地图；一幅图只承担一种信息类型。
7. **阈值标在图上，图注自足**：关键阈值、显著性线、参考线要画在图内并在图注中复述；每幅图注至少写清数据（N、来源）、方法（算法与参数）、颜色/符号编码、结论指向；节点数上千的网络图不要硬画全图，应抽样、聚合或交互呈现，并在图注中说明局限。
8. **复现信息进图注**：写清软件与版本、关键参数（如分级方法、投影、带宽/核函数）、数据与代码链接（DOI/仓库）；缺失则降级为“示意图”，不作论证图。

**反向评判结论**：默认出图离期刊水准的距离是系统性的——可视化域 19 个出图项目中，**无一默认带齐“图例+比例尺+指北针+数据来源”四件套**。最接近的是 Bertin.js（原生标题/脚注/比例尺/图例）、Observable Plot（投影+图例原生）与补验的 PyGMT 18 号图（标题+色带+经纬网，只缺比例尺/指北针）；渲染性能最好的 lonboard/deck.gl 默认连图例都没有。结论：**分析探索首选交互工具，投稿图一律要二次加工**，PyGMT/Cartopy 是静态出版收尾成本最低的路线。

## 六、谨慎采用清单

- **已停滞，勿作新选型**：GRAPE（最后提交 2024-02-24，且 PyPI 0.2.5 与仓库提交对应关系未证实）、geoplot（实质提交停于 2023-07-04）、Bertin.js（2023-10 后无推送）、fca（停于 2021）、TSGI（停于 2022）。
- **已断代，高 star 数具误导性**：jjsantos01/qgis_mcp（1,152 stars）在 mcp 1.x 与 2.x 下均无法启动，应选 nkarasiak 版（436 stars）。
- **许可证有坑**：prettymaps 是 AGPL-3.0（非早年博客说的 CC-BY-NC），商用/服务化须过法务；MapStore2 与 3D-Geo-Vis 2 **无许可证**（仓库无 LICENSE 文件，API 亦 NOASSERTION/空），引用前须先确认授权；skills-mcp 域 4/26 无 LICENSE 文件；server-google-maps 处于 MIT→Apache-2.0 过渡期。
- **仓库失联/名不副实**：community_TAU 的 GitHub 仓库不可达（PyPI wheel 实测通过，导入名已改为 tau_community_detection）；r2sfca 与 ejscreen 仓库 404；`pg-mcp` 只是文档站（源码已迁出）；`modelcontextprotocol/servers` 的 91,976 stars 与 K-Dense 的 57,064 stars 都是合集数，不能折算到单个项目。
- **机构断代**：EJScreen/CEJST 官网 2025 年初下线，EPA EJAM 2025 年中归档转 PEDP fork，CEJST v1.0 移交 DOI-DO/j40-cejst-2。
- **版本与依赖陷阱**：spml 开发版 0.1.dev1 有功能缺陷；EasyGraph 1.6.3 仍硬性要求 numpy<2 且全量依赖含 torch<2.0；prettymaps 上游 setup.py 仍用 Python 3.12 已移除的 API，只能源码导入；GeoVista 的 `add_base_layer` 与 PyVista 0.49.2 不兼容未解。
- **评估口径陷阱**：API `pushed_at` 与默认分支 HEAD 日期在 6 个项目上系统性不一致，评估活跃度应以 HEAD 与发版日期为准；skills-mcp 域 9 个“通过”仅为工具列表，无一次真实工具调用，“通过 ≠ 功能正确”。
- **“新”≠被采用**：2026 年新项目近 0 stars、采用证据多为作者自述；GeoLibre 半年 8.6k stars 的增速与作者既有受众高度相关，不宜直接等同于生产占有率。
