## 六、核心工具点评（22 个重点工具的实际用例与社区评价）

### 毫无争议的底座工具

- **GeoPandas + Shapely + Rasterio**：空间矢量/几何/栅格三件套，生态位无可替代。GeoPandas 大体量性能有短板（5 万行级即有内存溢出案例，大体量看 DuckDB Spatial、Sedona）；Rasterio 维护节奏偏慢（1.4.4 是时隔一年零十天的首个版本），但仍是默认选择。
- **ObsPy**：地震学标准库，NumFOCUS 背书、教程生态最完善；定位是离线处理，不是实时台网运行系统。
- **MetPy**：UCAR/Unidata 背书的气象通用库，BAMS 论文 + Project Pythia 配套。
- **FloPy**：USGS 官方 MODFLOW 接口，地下水数值模拟的默认入口；本身不解算物理，需另装 MODFLOW。
- **PySAL**：空间统计/计量的元包，子包生态大、学术引用广；它是库不是 GUI，终端用户改用 GeoDa。
- **Cartopy + IRIS**：Met Office/SciTools 系的制图与气象数据模型，小众但在其领域是刚需（IRIS 面临 xarray 的竞争）。
- **geemap**：GEE 生态的 Jupyter 入口，增长明确、NASA 资助，但强绑定 GEE 账号。

### 值得用、但要看场景

- **HoloViews/GeoViews**：可视化层而非分析库，大数据必须配 Datashader；适合交互探索。
- **xgcm**：Pangeo 基础设施，被 OceanSpy、ECCOv4-py 依赖；但只解决交错网格运算，功能面极窄。
- **NeuralHydrology**：降雨-径流深度学习的研究标杆（JOSS 论文、CAMELS 大样本），但属研究型工具、需 GPU。
- **Verde**：Fatiando 生态的网格化利器；官方明确不建议用于超过约 10,000 个点的大数据集，且 v2.0 有破坏性变更在途。
- **wrf-python**：NCAR 出品、WRF 后处理的默认选择，但只做后处理、版本迭代慢。
- **Landlab**：CSDMS/NSF 背书的地貌建模框架，适合搭积木式研究；不是开箱即用的模型，2D 为主。

### 谨慎采用

- **HydPy**：仅约 52 stars，社区极小且以德国机构为中心；虽有 BfG 业务委托、维护活跃，但兜底能力弱。
- **SPOTpy**：约 279 stars，问答渠道弱（README 仍写“联系作者”），接口偏老；只在需要其 16+ 率定算法合集时才值得引入。
- **Pastas**：荷兰中心、核心团队小，维护经费靠众筹；只做单点集总时间序列，不能替代三维地下水模拟。
- **Pyrocko**：震源/正演方向很强（GFZ 背书），但比 ObsPy 更专更小众，安装重；通用波形处理优先 ObsPy。
- **HyRiver**：仅支持美国境内数据、强依赖上游 Web 服务，README 仍标注“早期开发阶段，API 可能变化”。
- **VIC**：模型本身是水文领域标准（NASA LIS、UW 干旱系统都在用），但 Python 不是一等公民（C 核心、driver 仅用于测试）。

另有两点如实说明：Rasterio“NASA 在用”的说法仅见于教程、官网未核实；GeoPandas、Cartopy 的 USGS/NCAR/ECMWF 采用均未查到明确证据。

## 七、选型建议

1. **底座先定三件套**：GeoPandas + Shapely + Rasterio，再按领域叠加 ObsPy/MetPy/FloPy/PySAL，不会错。
2. **可视化按需叠加**：交互探索用 HoloViews/GeoViews（大数据配 Datashader），出版制图用 Cartopy，GEE 用户用 geemap。
3. **水文方向先查维护状态再引入**：HydPy、SPOTpy、Pastas、VIC 的 Python 侧都要先评估团队兜底能力；降雨径流优先看 NeuralHydrology（数据驱动）或 HydPy（物理框架）。
4. **清单里的停更项目不要直接装**：先看“四、五”两节，找同类维护中的替代品（如 xshape→geopandas、PyHIS→ulmo、PyCat→xclim/ibicus、PySDI→climate-indices）。
5. **注意一个更名**：BoM Water 原文链接 csiro-hydroinformatics/pybomwater 已重定向至 csiro/pybomwater（2026-09-29 仍有提交，活跃）。

## 九、方法与局限

- 星标与提交时间为 2026-11-14 快照；GitHub 随时会变，长期引用请以仓库页面为准。
- 最近提交取默认分支最新提交；个别仓库（如 VIC）其他分支有更新推送，API 的 pushed_at 会晚于默认分支提交，不影响“是否维护”的大结论。
- 核心工具的用例评价来自网络检索与官网/文档核验，未核实的内容已标注“未查到明确证据”，未编造用例与数字。
- 本报告只核验“仓库是否存在、是否维护、许可证是什么”以及重点工具的用例口碑，未对每个工具做安装实测；安装兼容性（如旧项目与新版 numpy/scipy 的冲突）需使用前自行验证。
