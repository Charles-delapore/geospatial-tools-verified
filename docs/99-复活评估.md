## 深评 1：Bruges（地球物理方程集）——分叉重发

- 仓库：agilescientific/bruges；323 stars；最后提交 2023-12-19《Pin NumPy》；未归档
- 用途：地震反射、岩石物理、滤波、子波、属性分析等地球物理方程集合；无等同维护中的替代包（零散公式可自写，但成体系的方程集没有）
- 许可证：**Apache-2.0**（LICENSE.txt 原文 + setup.cfg 分类一致）。分叉重发允许；须保留版权声明与 LICENSE 文本、注明修改；建议继续以 Apache-2.0 发布（最干净）。PyPI 包名 `bruges` 已被占用（最新 0.5.4），重发需换名（如 `bruges-ng`）。
- 账号活跃度：**长期不活跃**。近 3 年无提交；Issue #78（2019-02-15，energy 属性缺陷）至今未解决；PyPI 最新版停留在 0.5.4。可考虑分叉维护。
- 代码量级与测试：68 个 .py 文件，10,087 行；17 个测试文件，56 个测试；依赖仅 numpy + scipy（轻）。本机实测（系统 Python 3.12 + numpy 1.26.4）：56 个测试中 35 通过、2 失败、19 报错。
  - 19 个报错中 18 处源于测试代码使用的 `assertAlmostEquals` 在 Python 3.12 被移除（仓库内共 18 处），另 1 个是 `dip_test` 导入时缺 setuptools_scm 自动生成的 `_version.py`（安装打包问题，非算法问题）。
  - 2 个失败是岩石物理流体替换（Smith / Avseth）数值偏差约 22（期望 2210，得 2232），测试本身标注 “Cannot match :(”，须定位是真回归还是已知宽松测试。
  - 另须解除 setup.cfg 中 `numpy<2` 的钉死并逐项适配 numpy 2（上游最后一次提交就是 Pin NumPy，说明已感知该问题但未解决）。
- 改写面建议：**最小可用修复**即可——修测试别名、解除 numpy 钉死并适配、补 `_version.py` 生成、定位 2 个数值失败；不需要全面重构。风险点：数值结果须与原版逐项对齐验证（尤其流体替换与反射系数）。
- 路线：**分叉重发**——Apache-2.0 允许分叉，3 年无维护且修复点集中明确。

## 深评 2：EFlowCalc（生态径流特征计算器）——分叉重发（最优先）

- 仓库：ThibHlln/eflowcalc；10 stars；最后提交与发布均为 2021-04-26（v0.1.0）；未归档
- 用途：Olden and Poff (2003) 的 159 个生态相关径流特征指标（均值、极值、历时、变率等），向量化计算；无维护中的同类替代（Hydrostats / HydroErr 是拟合优度指标，不是径流特征）。
- 许可证：**GPLv3**（LICENCE.rst 为 GPLv3 全文，setup.py 一致）。分叉重发允许，但**衍生作品必须继续以 GPLv3 开源，不能改成 MIT**；须保留版权声明与许可证文本、注明修改、提供源码。PyPI 包名 `eflowcalc` 已被占用（最新 0.1.0），重发需换名（如 `eflowcalc-ng`）。
- 账号活跃度：**长期不活跃**。Snyk 判定 maintenance Inactive，0 个 open Issue、0 个 open PR，5 年无发布。可考虑分叉维护。
- 代码量级与测试：14 个 .py 文件，4,785 行；3 个测试文件；依赖仅 numpy + pandas（netCDF4 仅测试用）。本机实测：导入正常；doctest 12/12 通过；159 个指标逐项比对中 146 项通过，13 项（ma12、ma14、ma26、ma30、ma39、ml2、ml12、mh2、mh7、mh8 等）偏差仅约 1e-7 相对误差——系 float32 样例数据 / 版本漂移所致，放宽测试容差即可，不是算法错误。
- 改写面建议：**最小可用修复**——放宽 13 项测试的容差（或统一 float64）、补 Python 3.12 / 新版 pandas 兼容检查；不需要全面重构。风险点：很低，159 个指标的期望值已在测试中锚定，改动后逐项比对即可验证。
- 路线：**分叉重发**——GPLv3 下合法，库本身基本可跑、修复量最小，是五个深评库中最值得先做的。

## 深评 3：PyTOPKAPI（TOPKAPI 分布式水文模型）——分叉重发（低优先级）

- 仓库：sahg/PyTOPKAPI；23 stars；最后提交 2017-07-14；未归档
- 用途：Liu and Todini (2002) TOPKAPI 模型的 Python 实现，物理性、全分布式，曾用于多国流域与南非土壤湿度业务化应用；未发现维护中的 Python 版 TOPKAPI 替代（wflow.jl 是 Julia 且模型不同；SuperflexPy / HydPy 是概念性 / 集总式框架，不是 TOPKAPI）。
- 许可证：**BSD**（LICENSE 文件为 BSD 三条款原文，Copyright (c) 2007–2017 PyTOPKAPI Developers）。分叉重发允许；须保留版权声明、条件清单与免责声明；重发可保留 BSD。PyPI：搜索可见项目页，但 2026-11-14 用 pip 查不到任何可安装版本（可能无发布文件）；重发前须先在 PyPI 核实名称状态。
- 账号活跃度：**长期不活跃**。9 年多无提交；Issue / PR 回应情况未查到。
- 代码量级与测试：29 个 .py 文件，6,469 行；3 个测试文件（nosetests 时代）；依赖 numpy / scipy / h5py / networkx / tqdm，另加 R（`rpy`）与 GRASS GIS（参数生成流程）。本机实测：Python 3.12 下 `import pytopkapi` 即失败——`from configparser import SafeConfigParser`（3.12 已移除）；另有多处 `from numpy import *` / `from scipy import *`；`rpy`（RPy，已死亡，今为 rpy2）仅用于 `interpolation.py` 一个文件的 R gstat 克里金，可去掉或改 scipy 实现。未跑通任何测试。
- 改写面建议：**最小可用修复**——ConfigParser 替换、去掉 rpy（改 scipy 克里金或 pykrige）、清理 star import；先用自带 `example_simulation` 做端到端运行与数值对齐验证；参数生成（GRASS GIS）部分先搁置，不纳入首版。风险点：中等——模型是分布式物理模型，数值对齐验证工作量大；且完整工作流依赖 GRASS GIS 制备流域参数，重依赖部分不符合轻量标准，首版只能覆盖“模型核”而非全流程。
- 路线：**分叉重发（低优先级）**——唯一 Python 版 TOPKAPI 且 BSD 许可，修复点集中；但验证成本高于前两个，排在后面。
